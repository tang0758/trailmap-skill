# Trailmap v0.2.0 Subagent 回归测试用例

本文档用于验证 Trailmap `v0.2.0` 的功能。`v0.2.0` 在 `v0.1.0` 基础路径管理能力之上新增 subagent 并行探索能力。`v0.2.0` 不包含 worktree 隔离能力；任何 `--worktree` 行为都不属于本版本测试范围。

## 测试范围

- `v0.1.0` 基础路径管理回归
- `agent_run` 执行状态模型
- 为已有非 active path 启动 subagent
- 为新建非 active path 启动 subagent
- `clean` 与 `--informed` subagent 上下文模式
- shared workspace 代码风险提示与 `--allow-shared-code`
- subagent report 到普通 `update <key>` 草案的确认流
- `list`、`show`、`map`、`map text` 中的紧凑 subagent 状态展示
- subagent 相关负向场景

## 不测试范围

- `--worktree`
- `--base <ref>`
- 自动创建 Git worktree
- 自动 merge、commit、stash、revert、cherry-pick 或 apply patch
- 多条主 active path
- subagent 直接写入 `.trailmap/marks/`

## 测试准备

### 环境

- 安装版本：`v0.2.0`
- Codex 调用方式：`$trailmap`
- Claude Code 调用方式：`/trailmap`
- 本文示例统一使用 Codex 语法。

### 清理状态

在测试 workspace 中清空 Trailmap 状态：

```powershell
Remove-Item -Recurse -Force .trailmap -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .codex\marks -ErrorAction SilentlyContinue
```

### 前置回归

先完整执行：

```text
docs/testing/v0.1.0-basic-regression.zh-CN.md
```

期望：

- `v0.1.0` 基础功能全部通过。
- `list`、`show`、`map`、`map text` 行为仍与基础回归一致。
- 未使用 subagent 时，不应出现 `agent_run` 字段。

### 通用验收规则

- 所有写操作必须先展示确认草案，明确确认后才写入状态。
- `--allow-shared-code` 只跳过共享工作区风险的二次提示，不跳过写入确认草案。
- subagent 是执行状态叠加，不改变 path 生命周期状态含义。
- 任意时刻每个 topic 最多只有一条主 `active` path。
- subagent path 不能因为启动 subagent 而变成第二条 `active` path。
- `agent_run.status` 只能是 `running`、`reported`、`completed`、`failed`、`blocked` 或 `cancelled`。
- `agent_run.mode` 必须是 `subagent`。
- `agent_run.context_mode` 默认是 `clean`，使用 `--informed` 时是 `informed`。
- Trailmap 不应自动 stash、revert、commit、创建或切换 Git 分支。

## 测试数据基线

执行以下命令创建基础 topic：

```text
$trailmap 登录失败可能来自 token 刷新、网络重试或缓存未更新，先检查 token 刷新。
```

确认后期望：

```text
A  Token 刷新排查  [active]
B  网络重试排查    [pending]
C  缓存未更新      [pending]
```

校验点：

- A 是唯一 active path。
- B/C 是 root pending path。
- B/C 没有 `agent_run` 字段。

## 测试用例

### TC-201 为已有 pending path 启动 subagent

命令：

```text
$trailmap subagent B --allow-shared-code
```

确认前期望：

- 展示 subagent startup 确认草案。
- 草案包含 path key/title/status。
- 草案显示 `context_mode = clean`。
- 草案显示计划写入 `agent_run.status = running`。
- 草案包含 shared workspace code risk 摘要。
- 即使使用 `--allow-shared-code`，仍必须要求确认写入。

确认后期望：

```text
A  Token 刷新排查  [active]
B  网络重试排查    [pending, subagent running]
C  缓存未更新      [pending]
```

校验点：

- A 仍然是唯一 active path。
- B 的生命周期状态仍是 `pending`。
- B 顶层新增 `agent_run`。
- `agent_run.status = "running"`。
- `agent_run.mode = "subagent"`。
- `agent_run.context_mode = "clean"`。
- `agent_run.risk = "shared_workspace_code"`。

### TC-202 默认 shared workspace 风险提示

前置条件：

- C 是 pending path。
- C 没有 `agent_run`。

命令：

```text
$trailmap subagent C
```

确认前期望：

- 展示 shared workspace 代码风险提示。
- 提示 subagent 和当前 active path 可能同时修改同一批文件。
- 要求用户明确接受风险或确认继续。
- 展示 Trailmap 写入确认草案。

确认后期望：

- C 仍是 `pending`。
- C 获得 `agent_run.status = "running"`。
- A 仍是唯一 active path。

### TC-203 `--informed` subagent 上下文

前置条件：

- A 有至少一条 update。
- B 是 pending 或 paused path，且没有 `agent_run.status = running`。

命令：

```text
$trailmap subagent B --informed --allow-shared-code
```

确认前期望：

- 草案显示 `context_mode = informed`。
- 草案说明会向 subagent 提供 sibling、parent、当前 active 或已探索路径的摘要结论。
- 其他路径内容必须标记为“其他路径上下文”。

确认后期望：

- B 的生命周期状态保持原值。
- B 的 `agent_run.context_mode = "informed"`。
- B 的 `agent_run.status = "running"`。
- A 仍是唯一 active path。

### TC-204 `pending <idea> --subagent`

命令：

```text
$trailmap pending 可能是服务端限流导致登录失败 --subagent --allow-shared-code
```

确认前期望：

- 展示新增 sibling pending path 草案。
- 草案明确当前 active path 不变。
- 草案显示新 path 将获得 `agent_run.status = running`。
- 草案包含 shared workspace 风险摘要。

确认后期望：

```text
A  Token 刷新排查  [active]
D  服务端限流      [pending, subagent running]
```

校验点：

- 新 path 与当前 active path 拥有相同 parent。
- 新 path 状态是 `pending`。
- 新 path 有 `agent_run.status = "running"`。
- `topic.active` 不变。
- 当前 active path 不追加离开摘要。

### TC-205 根路径创建时指定 `--subagent B`

前置条件：

- 清空 Trailmap 状态，或使用新 workspace。

命令：

```text
$trailmap 支付失败可能来自订单状态或支付网关，先查订单状态 --subagent B --allow-shared-code
```

确认前期望：

- 创建新 topic 的确认草案。
- A 是默认 active path。
- B 是 pending path。
- B 被选中启动 subagent。
- 草案显示 B 将获得 `agent_run.status = running`。

确认后期望：

```text
A  订单状态排查  [active]
B  支付网关排查  [pending, subagent running]
```

校验点：

- A 是唯一 active path。
- B 的生命周期状态是 `pending`。
- B 有 `agent_run.status = "running"`。
- 不存在第二条 active path。

### TC-206 根路径创建时指定多个 subagent path

前置条件：

- 清空 Trailmap 状态，或使用新 workspace。

命令：

```text
$trailmap 搜索结果异常可能来自索引延迟、查询缓存或排序规则，先查索引延迟 --subagent B,C --allow-shared-code
```

确认后期望：

```text
A  索引延迟  [active]
B  查询缓存  [pending, subagent running]
C  排序规则  [pending, subagent running]
```

校验点：

- A 是唯一 active path。
- B/C 均保持 `pending`。
- B/C 均有 `agent_run.status = "running"`。
- B/C 的 `agent_run` 互相独立。

### TC-207 child paths 创建时指定 subagent path

前置条件：

- A 是当前 active path。

命令：

```text
$trailmap token 刷新内部可能是刷新竞态或缓存写入顺序，先查刷新竞态 --subagent A2 --allow-shared-code
```

确认后期望：

```text
A   Token 刷新排查  [paused]
A1  刷新竞态        [active]
A2  缓存写入顺序    [pending, subagent running]
```

校验点：

- A 从 `active` 变为 `paused`。
- A1 是唯一 active path。
- A2 的 `parent = "A"`。
- A2 的生命周期状态是 `pending`。
- A2 有 `agent_run.status = "running"`。

### TC-208 未指定 `--subagent` 时询问候选 path

前置条件：

- A 是当前 active path。

命令：

```text
$trailmap token 刷新内部可能是刷新竞态或缓存写入顺序，先查刷新竞态。
```

确认前期望：

- 由于命令会创建非 active path，Trailmap 应询问是否为候选 path 启动 subagent。
- 候选列表包含将成为 pending 的 path。
- 用户可以选择 0 条、1 条或多条。

选择 0 条并确认后期望：

- 新 pending path 不包含 `agent_run`。
- 其他基础 child path 行为与 `v0.1.0` 一致。

选择 1 条或多条并确认后期望：

- 被选择的 pending path 获得 `agent_run.status = "running"`。
- 未选择的 pending path 不包含 `agent_run`。

### TC-218 resume 正在 subagent 探索的 path

前置条件：

- B 是 pending path。
- B 有 `agent_run.status = "running"`。
- A 是当前 active path。

命令：

```text
$trailmap resume B clean
```

确认前期望：

- 展示普通 resume 确认草案。
- 明确警告 B 正在被 subagent 探索。
- 警告说明主会话 resume B 可能造成重复工作或上下文混合。
- 不要求 `--force`。

确认后期望：

- B 可以变为主 active path。
- 原 active path A 变为 `paused` 或草案中明确的非 active 状态。
- B 的 `agent_run.status = "running"` 保留。
- 仍然只有一条主 active path。

### TC-219 subagent report 进入 reported 状态

前置条件：

- B 有 `agent_run.status = "running"`。
- subagent 返回报告。

subagent 报告格式：

```text
path_key: B
summary: 检查了网络重试路径。
conclusion: 网络重试错误映射可能导致登录失败。
status_after: paused
codechange.changed: false
codechange.files: []
codechange.summary: 只读排查，没有修改代码。
handoff: 建议主会话继续确认重试错误码映射。
```

期望：

- Trailmap 将 B 的 `agent_run.status` 标记或展示为 `reported`。
- Trailmap 生成普通 `update B` 草案。
- 草案包含 summary、conclusion、status_after、codechange。
- 未确认 update 草案前，不追加 B 的 updates。
- 未确认 update 草案前，不把 `agent_run.status` 改为 `completed`。

### TC-220 确认 subagent report update

前置条件：

- B 有 `agent_run.status = "reported"`。
- Trailmap 已展示由 subagent report 转换出的 `update B` 草案。

操作：

- 确认写入 update 草案。

确认后期望：

- B 追加一条 update。
- B 顶层状态同步为 report 的 `status_after`。
- `agent_run.status = "completed"`。
- 如果 `status_after` 不是 `closed`，B 顶层不应出现关闭字段。
- subagent 的 handoff 摘要可在 `show B` 中看到。

### TC-221 拒绝 subagent report update

前置条件：

- C 有 `agent_run.status = "reported"`。
- Trailmap 已展示由 subagent report 转换出的 `update C` 草案。

操作：

- 拒绝或取消确认 update 草案。

期望：

- C 不追加 update。
- C 生命周期状态不变。
- `agent_run.status` 保持 `reported`。
- Trailmap 不修改代码，不回滚代码。

### TC-222 subagent 建议关闭 path

前置条件：

- B 有 `agent_run.status = "running"`。
- subagent 返回 `status_after = closed`。

subagent 报告格式：

```text
path_key: B
summary: 已验证网络重试不是主因。
conclusion: 登录失败与网络重试无关。
status_after: closed
closed_as: discarded
codechange.changed: false
codechange.files: []
codechange.summary: 只读排查，没有修改代码。
handoff: 可回到 token 刷新或缓存方向继续。
```

确认前期望：

- Trailmap 只生成普通 `update B` 草案。
- 草案显示 `status_after = closed` 和 `closed_as = discarded`。
- 明确需要用户确认。
- subagent 不能直接关闭 path。

确认后期望：

- B 状态变为 `closed`。
- B 顶层包含 `closed_as = "discarded"`。
- B 顶层包含 `closed_reason` 和 `closed_at`。
- `agent_run.status = "completed"`。
- 如果 B 不是主 active path，不影响 `topic.active`。

## 最终验收清单

完成全部测试后，检查状态文件满足以下条件：

- `v0.1.0` 基础回归仍通过。
- 每个 topic 最多一条主 active path。
- subagent path 的生命周期状态仍是 `pending`、`paused` 或其他原本状态，不因 subagent 自动变为 `active`。
- `agent_run` 只表示执行状态，不替代 path 生命周期状态。
- `agent_run.status` 使用合法枚举值。
- `agent_run.mode = "subagent"`。
- `agent_run.context_mode` 使用 `clean` 或 `informed`。
- `list`、`show`、`map`、`map text` 都能展示紧凑 subagent 状态。
- subagent report 必须经过用户确认才写入 path update。
- 拒绝 subagent report update 时，`agent_run.status` 保持 `reported`。
- `--allow-shared-code` 不跳过 Trailmap 写入确认。
- 共享工作区风险在未显式接受时可见。
- 不存在 `agent_run.worktree` 或任何 worktree 元数据。
- 测试过程中没有发生 Trailmap 自动 Git 操作。
