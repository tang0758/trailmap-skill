# Trailmap v0.1.0 基础回归测试用例

本文档用于验证 Trailmap `v0.1.0` 的基础功能。`v0.1.0` 不包含 subagent、worktree 或并行执行能力；这些能力不属于本测试范围。

## 测试范围

- 创建主题、根路径和 child paths
- 新增 sibling pending path
- `list`、`show`、`map`、`map text` 只读视图
- `update` 记录路径进展
- `resume clean` 与 `resume informed`
- `close done|blocked|discarded`
- `rename` 重命名活跃主题
- 数据模型不变量和存储目录兼容性

## 测试准备

### 环境

- 安装版本：`v0.1.0`
- Codex 调用方式：`$trailmap`
- Claude Code 调用方式：`/trailmap`
- 本文示例统一使用 Codex 语法。

### 清理状态

在测试 workspace 中清空 Trailmap 状态：

```powershell
Remove-Item -Recurse -Force .trailmap -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .codex\marks -ErrorAction SilentlyContinue
```

### 通用验收规则

- 所有写操作必须先展示确认草案，明确确认后才写入状态。
- 只读操作不要求确认，也不修改状态文件。
- 任意时刻每个 topic 最多只有一条 `active` path。
- `topic.active` 必须等于唯一 active path 的 key；没有 active path 时必须为 `null`。
- closed path 必须包含 `closed_as`，取值只能是 `done`、`blocked` 或 `discarded`。
- 非 closed path 不应保留顶层 `closed_as`、`closed_reason`、`closed_at`。
- Trailmap 不应自动 stash、revert、commit、创建或切换 Git 分支。

## 测试用例

### TC-001 创建根路径

命令：

```text
$trailmap 登录失败可能来自 token 刷新或网络重试，先检查 token 刷新。
```

确认前期望：

- 展示简洁确认草案。
- 草案包含一个 active root path 和至少一个 pending root path。
- 未确认前不写入 `.trailmap/marks/`。

确认后期望：

```text
A  Token 刷新排查  [active]
B  网络重试排查    [pending]
```

校验点：

- 创建 `.trailmap/marks/index.json`。
- 创建一个 topic JSON 文件。
- `topic.active = "A"`。
- 只有 A 的 `status` 是 `active`。
- B 的 `status` 是 `pending`。
- A/B 的 `parent` 都是 `null`。

### TC-002 list 查看工作台

命令：

```text
$trailmap list
```

期望：

- 不需要确认。
- 能看到当前 topic。
- A 显示为 `active`。
- B 显示为 `pending`。
- closed path 只显示关闭摘要，不展开完整 updates。
- 命令执行后状态文件不变。

### TC-003 show 当前主题

命令：

```text
$trailmap show
```

期望：

- 不需要确认。
- 显示活跃主题。
- 显示当前 active path A。
- 显示 pending path B。
- 如果没有 closed path，不显示关闭字段。
- 命令执行后状态文件不变。

### TC-004 show 指定 path

命令：

```text
$trailmap show B
```

期望：

- 不需要确认。
- 只展示活跃主题内 B 的详情。
- 包含 B 的 `created_from`、path 描述、updates、codechange 详情和状态。
- B 仍然是 `pending`。
- 命令执行后状态文件不变。

### TC-005 原地新增 sibling pending path

命令：

```text
$trailmap pending 可能是系统时间偏差导致，先记录，不切换当前路径。
```

确认前期望：

- 展示新增 pending path 的确认草案。
- 草案明确当前 active path 不变。

确认后期望：

```text
A  Token 刷新排查  [active]
B  网络重试排查    [pending]
C  系统时间偏差    [pending]
```

校验点：

- A 仍然是唯一 active path。
- C 的 `status` 是 `pending`。
- C 的 `parent` 与 A 相同，都是 `null`。
- 不应为 A 自动追加离开摘要。
- `topic.active` 仍为 `"A"`。

### TC-006 当前路径内部分叉为 child paths

命令：

```text
$trailmap token 刷新内部可能是刷新竞态，也可能是缓存未更新，先查刷新竞态。
```

确认前期望：

- 展示 child path 创建草案。
- 草案说明当前 active path A 将变为 `paused`。
- 草案说明新 child path 的 parent 是 A。

确认后期望：

```text
A   Token 刷新排查  [paused]
A1  刷新竞态        [active]
A2  缓存未更新      [pending]
B   网络重试排查    [pending]
C   系统时间偏差    [pending]
```

校验点：

- A 从 `active` 变为 `paused`。
- A1 是唯一 active path。
- A1/A2 的 `parent = "A"`。
- B/C 仍是 root pending path，`parent = null`。
- `topic.active = "A1"`。
- A 追加一条离开摘要 update。

### TC-007 map 输出 Mermaid

命令：

```text
$trailmap map
```

期望：

- 不需要确认。
- 输出 Mermaid `graph LR`。
- 使用 `root` 表示 topic 节点。
- root 指向 A/B/C。
- A 指向 A1/A2。
- 节点标签包含 path key、title 和 status。
- closed path 的标签包含 `closed: <closed_as>`。
- 不展开完整 updates。
- 命令执行后状态文件不变。

### TC-008 map text 输出文本树

命令：

```text
$trailmap map text
```

期望：

- 不需要确认。
- 输出纯文本树。
- 层级关系与 `map` 一致。
- A1 显示为 `active`。
- A2 显示为 `pending`。
- B/C 显示为 root pending path。
- 命令执行后状态文件不变。

### TC-009 update 当前 active path

命令：

```text
$trailmap update A1 已检查刷新竞态，没有发现并发刷新冲突，暂停这个方向，没有修改代码。
```

确认前期望：

- 展示 update 确认草案。
- 草案包含 path key、摘要、结论、`status_after` 和 codechange 摘要。

确认后期望：

- A1 追加一条 update。
- update 包含 `time`、`summary`、`conclusion`、`status_after`、`codechange`。
- A1 顶层状态与 `status_after` 同步。
- 如果 `status_after` 不是 `closed`，A1 顶层不应出现 `closed_as`、`closed_reason`、`closed_at`。
- 如果记录为只读排查，`codechange.changed = false` 且 `codechange.files = []`。

### TC-010 resume pending path clean

前置条件：

- 当前 topic 存在 pending path B。
- 当前 active path 是 A1 或其他非 B path。

命令：

```text
$trailmap resume B clean
```

确认前期望：

- 展示 resume 确认草案。
- 草案包含当前 active path 的离开摘要。
- 草案显示目标 path B 和模式 `clean`。
- 如存在未提交代码改动，草案提示 clean resume 可能受工作区污染。

确认后期望：

- B 变为 `active`。
- 原 active path 不再是 `active`，通常变为 `paused`。
- `topic.active = "B"`。
- clean 上下文只包含 B 自己的 `created_from`、title、goal、hypothesis、updates、constraints 和代码改动警告。
- clean 上下文不带入 sibling paths 的详细推理。

### TC-011 resume paused child path informed

前置条件：

- A2 是 pending 或 paused path。
- 当前 active path 不是 A2。

命令：

```text
$trailmap resume A2 informed
```

确认前期望：

- 展示 resume 确认草案。
- 草案显示目标 path A2 和模式 `informed`。

确认后期望：

- A2 变为 `active`。
- 原 active path 变为 `paused` 或草案中明确的非 active 状态。
- `topic.active = "A2"`。
- informed 上下文包含 clean 的全部内容。
- sibling、parent 或已探索路径摘要必须标记为“其他路径上下文”。
- 其他路径结论不能被写成 A2 自己已确认的事实。

### TC-012 close pending path discarded

命令：

```text
$trailmap close C discarded
```

确认前期望：

- 展示 close 确认草案。
- 草案包含 path key、`closed_as = discarded`、关闭原因、最终摘要和 codechange 摘要。

确认后期望：

- C 的 `status` 变为 `closed`。
- C 顶层包含 `closed_as = "discarded"`。
- C 顶层包含 `closed_reason`。
- C 顶层包含 `closed_at`。
- C 追加一条 closing update。
- C 不再显示为 pending path，应在 closed 区域或 closed 标签中展示。

### TC-013 close active path done

前置条件：

- 当前 active path 是 A2。

命令：

```text
$trailmap close A2 done
```

确认前期望：

- 展示 close 确认草案。
- 草案说明关闭的是当前 active path。

确认后期望：

- A2 的 `status` 变为 `closed`。
- A2 顶层包含 `closed_as = "done"`。
- A2 顶层包含 `closed_reason` 和 `closed_at`。
- `topic.active = null`。
- Trailmap 不自动激活其他 pending path。

### TC-014 resume closed path

前置条件：

- C 已经是 `closed`，且 `closed_as = "discarded"`。

命令：

```text
$trailmap resume C clean
```

确认前期望：

- 明确警告目标 path 已 closed。
- 明确说明本次操作会重新打开 C。
- 展示目标 path、resume 模式和状态变化。

确认后期望：

- C 变为 `active`。
- `topic.active = "C"`。
- C 顶层移除 `closed_as`、`closed_reason`、`closed_at`。
- 历史关闭记录仍保留在 C 的 `updates` 中。
- 当前没有第二条 active path。

### TC-015 rename 活跃主题

命令：

```text
$trailmap rename 登录失败排查基础回归
```

确认前期望：

- 展示 rename 确认草案。
- 草案只涉及 topic title。

确认后期望：

- 只修改当前活跃 topic 的 title。
- 不修改任何 path key。
- 不修改任何 path title。
- `list`、`show`、`map` 都显示新的 topic title。

### TC-016 非法 key 只读与写操作

命令：

```text
$trailmap show Z
$trailmap resume Z clean
$trailmap close Z discarded
```

期望：

- `show Z` 不写状态，提示 key 不存在。
- `resume Z clean` 不应生成可确认写入，提示 key 不存在。
- `close Z discarded` 不应生成可确认写入，提示 key 不存在。
- 原 topic 状态完全不变。

### TC-017 resume 缺少模式

命令：

```text
$trailmap resume B
```

期望：

- 不直接写入状态。
- 要求选择 `clean` 或 `informed`。
- 原 topic 状态完全不变。

### TC-018 close 缺少分类

命令：

```text
$trailmap close B
```

期望：

- 不直接写入状态。
- 要求选择 `done`、`blocked` 或 `discarded`。
- 原 topic 状态完全不变。

### TC-019 show topic_id 不受支持

前置条件：

- 通过 `list` 获取一个 topic id，例如 `login-timeout`。

命令：

```text
$trailmap show login-timeout
```

期望：

- 不将 topic id 当作 path key 成功展示。
- 提示 `v1` 不支持 `show <topic_id>`，或提示当前活跃主题内没有该 path key。
- 状态不变。

### TC-020 跨主题 resume

前置条件：

- 已存在两个 topic。
- 第二个 topic 中存在 path A。
- 当前 `index.active_topic_id` 指向第一个 topic。

命令：

```text
$trailmap resume <topic_id> A clean
```

期望：

- 展示跨主题 resume 确认草案。
- 确认后 `index.active_topic_id` 更新为目标 topic id。
- 目标 topic 的 A 变为 `active`。
- 原活跃 topic 的 active path 离开并变为 `paused`，除非草案中有更具体状态。
- 不自动修改 Git 状态。

### TC-021 旧存储目录兼容

前置条件：

- 不存在 `.trailmap/marks/`。
- 存在旧目录 `.codex/marks/`，且其中有合法 Trailmap 状态。

命令：

```text
$trailmap list
```

期望：

- 能继续读取 `.codex/marks/`。
- 不强制迁移到 `.trailmap/marks/`。
- 除非用户明确要求，不创建迁移副作用。
- 只读命令不修改状态文件。

### TC-022 写操作取消确认

命令：

```text
$trailmap pending 可能是服务端限流，先记录。
```

操作：

- 在确认草案出现后拒绝或取消确认。

期望：

- 不新增 path。
- 不修改 `index.json`。
- 不修改 topic JSON。
- 当前 active path 不变。

### TC-023 代码改动安全提示

前置条件：

- 在 workspace 中制造一个未提交代码改动。
- 当前 active path 是 A。
- B 是 pending path。

命令：

```text
$trailmap resume B clean
```

确认前期望：

- 确认草案提示当前 workspace 代码改动可能污染 clean resume。
- 草案不承诺自动隔离或回滚工作区。

确认后期望：

- Trailmap 只记录相关 codechange 警告或摘要。
- 不自动 stash、revert、commit、创建或切换 Git 分支。
- 工作区未提交代码改动仍然存在。

## 最终验收清单

完成全部测试后，检查状态文件满足以下条件：

- 每个 topic 最多一条 active path。
- `topic.active` 与 active path 一致；没有 active path 时为 `null`。
- 所有 path 的 `parent` 要么是 `null`，要么引用同 topic 内存在的 path key。
- closed path 都有合法 `closed_as`。
- 非 closed path 没有顶层关闭字段。
- `updates` 中的 `status_after` 与路径顶层状态变更可解释。
- `list`、`show`、`map`、`map text` 展示的路径状态一致。
- `.trailmap/marks/` 或兼容的 `.codex/marks/` 中状态 JSON 可解析。
- 测试过程中没有发生 Trailmap 未经确认的状态写入。
- 测试过程中没有发生 Trailmap 自动 Git 操作。
