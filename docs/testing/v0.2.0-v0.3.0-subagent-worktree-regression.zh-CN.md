# Trailmap v0.2.0 + v0.3.0 Subagent/Worktree 回归测试用例

本文档用于联合验证 Trailmap `v0.2.0` 与 `v0.3.0` 的功能。`v0.2.0` 在 `v0.1.0` 基础路径管理能力之上新增 subagent 并行探索能力；`v0.3.0` 在此基础上新增显式 opt-in 的 subagent worktree 隔离执行能力。

当前仓库尚未看到 `v0.3.0` tag 时，可将 `v0.3.0` 理解为当前 HEAD 中的 worktree 功能候选集。

## 测试范围

- `v0.1.0` 基础路径管理回归
- `agent_run` 执行状态模型
- 为已有非 active path 启动 subagent
- 为新建非 active path 启动 subagent
- `clean` 与 `--informed` subagent 上下文模式
- shared workspace 代码风险提示与 `--allow-shared-code`
- subagent report 到普通 `update <key>` 草案的确认流
- `list`、`show`、`map`、`map text` 中的紧凑 subagent 状态展示
- subagent 相关负向场景
- `--worktree` 隔离执行模式
- `--base <ref>` worktree base 选择
- `.worktrees/` 与 `.gitignore` 安全处理
- `agent_run.worktree` 数据模型
- worktree report、retained worktree、resume warning

## 版本边界与不测试范围

- `v0.2.0` 不支持 `--worktree` 或 `--base <ref>`；TC-224 和 TC-225 用于验证该版本边界。
- `v0.3.0` 支持 `--worktree`，但必须显式 opt-in；shared workspace 仍是默认 subagent 模式。
- 自动 merge、commit、stash、revert、cherry-pick 或 apply patch
- 自动清理 worktree
- 自动复制 worktree 改动回主工作区
- 多条主 active path
- subagent 直接写入 `.trailmap/marks/`

## 测试准备

### 环境

- 安装版本：`v0.2.0` 与 `v0.3.0` 候选版本分别测试
- Codex 调用方式：`$trailmap`
- Claude Code 调用方式：`/trailmap`
- 本文示例统一使用 Codex 语法。

### 清理状态

在测试 workspace 中清空 Trailmap 状态：

```powershell
Remove-Item -Recurse -Force .trailmap -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .codex\marks -ErrorAction SilentlyContinue
```

### 前置回归

先完整执行：

```text
docs/testing/v0.1.0-basic-regression.zh-CN.md
```

期望：

- `v0.1.0` 基础功能全部通过。
- `list`、`show`、`map`、`map text` 行为仍与基础回归一致。
- 未使用 subagent 时，不应出现 `agent_run` 字段。

执行 `v0.3.0` worktree 用例前，先完整执行本文的 `v0.2.0` subagent 用例，确认 shared workspace subagent 行为没有回退。

### 通用验收规则

- 所有写操作必须先展示确认草案，明确确认后才写入状态。
- `--allow-shared-code` 只跳过共享工作区风险的二次提示，不跳过写入确认草案。
- subagent 是执行状态叠加，不改变 path 生命周期状态含义。
- 任意时刻每个 topic 最多只有一条主 `active` path。
- subagent path 不能因为启动 subagent 而变成第二条 `active` path。
- `agent_run.status` 只能是 `running`、`reported`、`completed`、`failed`、`blocked` 或 `cancelled`。
- `agent_run.mode` 必须是 `subagent`。
- `agent_run.context_mode` 默认是 `clean`，使用 `--informed` 时是 `informed`。
- `agent_run.worktree` 只允许出现在 `--worktree` run 中。
- 除 `--worktree` 确认后创建隔离 branch/worktree 外，Trailmap 不应自动 stash、revert、commit、创建或切换 Git 分支。

## 测试数据基线

执行以下命令创建基础 topic：

```text
$trailmap 登录失败可能来自 token 刷新、网络重试或缓存未更新，先检查 token 刷新。
```

确认后期望：

```text
A  Token 刷新排查  [active]
B  网络重试排查    [pending]
C  缓存未更新      [pending]
```

校验点：

- A 是唯一 active path。
- B/C 是 root pending path。
- B/C 没有 `agent_run` 字段。

## 测试用例

### TC-201 为已有 pending path 启动 subagent

命令：

```text
$trailmap subagent B --allow-shared-code
```

确认前期望：

- 展示 subagent startup 确认草案。
- 草案包含 path key/title/status。
- 草案显示 `context_mode = clean`。
- 草案显示计划写入 `agent_run.status = running`。
- 草案包含 shared workspace code risk 摘要。
- 即使使用 `--allow-shared-code`，仍必须要求确认写入。

确认后期望：

```text
A  Token 刷新排查  [active]
B  网络重试排查    [pending, subagent running]
C  缓存未更新      [pending]
```

校验点：

- A 仍然是唯一 active path。
- B 的生命周期状态仍是 `pending`。
- B 顶层新增 `agent_run`。
- `agent_run.status = "running"`。
- `agent_run.mode = "subagent"`。
- `agent_run.context_mode = "clean"`。
- `agent_run.risk = "shared_workspace_code"`。

### TC-202 默认 shared workspace 风险提示

前置条件：

- C 是 pending path。
- C 没有 `agent_run`。

命令：

```text
$trailmap subagent C
```

确认前期望：

- 展示 shared workspace 代码风险提示。
- 提示 subagent 和当前 active path 可能同时修改同一批文件。
- 要求用户明确接受风险或确认继续。
- 展示 Trailmap 写入确认草案。

确认后期望：

- C 仍是 `pending`。
- C 获得 `agent_run.status = "running"`。
- A 仍是唯一 active path。

### TC-203 `--informed` subagent 上下文

前置条件：

- A 有至少一条 update。
- B 是 pending 或 paused path，且没有 `agent_run.status = running`。


确认前期望：

- 草案显示 `context_mode = informed`。
- 草案说明会向 subagent 提供 sibling、parent、当前 active 或已探索路径的摘要结论。
- 其他路径内容必须标记为“其他路径上下文”。

确认后期望：

- B 的生命周期状态保持原值。
- B 的 `agent_run.context_mode = "informed"`。
- B 的 `agent_run.status = "running"`。
- A 仍是唯一 active path。

### TC-204 `pending <idea> --subagent`

命令：


- 草案明确当前 active path 不变。

确认后期望：


### TC-208 未指定 `--subagent` 时询问候选 path

### TC-219 subagent report 进入 reported 状态

前置条件：

- B 有 `agent_run.status = "running"`。
- subagent 返回报告。

subagent 报告格式：

```text
path_key: B
summary: 检查了网络重试路径。
conclusion: 网络重试错误映射可能导致登录失败。
status_after: paused
codechange.changed: false
codechange.files: []
codechange.summary: 只读排查，没有修改代码。
handoff: 建议主会话继续确认重试错误码映射。
```

期望：

- Trailmap 将 B 的 `agent_run.status` 标记或展示为 `reported`。
- Trailmap 生成普通 `update B` 草案。
- 草案包含 summary、conclusion、status_after、codechange。
- 未确认 update 草案前，不追加 B 的 updates。
- 未确认 update 草案前，不把 `agent_run.status` 改为 `completed`。

## v0.3.0 Worktree 测试用例

### TC-301 默认 subagent 仍为 shared workspace

前置条件：

- 使用 `v0.3.0` 候选版本。
- B 是 pending path。

命令：

```text
$trailmap subagent B --allow-shared-code
```

期望：

- 行为与 `v0.2.0` shared workspace subagent 一致。
- B 获得 `agent_run.status = "running"`。
- B 不包含 `agent_run.worktree`。
- 不创建 `.worktrees/`。
- 不创建 Git branch。
- shared workspace 仍是默认模式。

### TC-302 为已有 path 启动 worktree subagent

前置条件：

- B 是 pending path。
- B 没有 `agent_run.status = running` 或 `reported`。

命令：

```text
$trailmap subagent B --worktree
```

确认前期望：

- 展示 worktree 启动确认草案。
- 草案包含 path key/title/status。
- 草案包含 context mode。
- 草案包含 base ref 和 base sha。
- 草案包含将创建的 branch。
- 草案包含将创建的 worktree path。
- 草案说明主工作区未提交改动不会复制到 worktree。
- 草案说明 Trailmap 不会自动 merge、commit、stash、revert 或 apply 改动。
- 未确认前不创建 branch、worktree 或状态写入。

确认后期望：

- B 的生命周期状态仍是 `pending`。
- B 获得 `agent_run.status = "running"`。
- `agent_run.mode = "subagent"`。
- `agent_run.context_mode = "clean"`。
- `agent_run.worktree.enabled = true`。
- `agent_run.worktree.status = "ready"`。
- `agent_run.worktree.path` 指向 `.worktrees/trailmap/<topic-id>/<path-key>/`。
- `agent_run.worktree.branch` 指向 `trailmap/<topic-id>/<path-key>`。

## 最终验收清单

完成全部测试后，检查状态文件满足以下条件：

- `v0.1.0` 基础回归仍通过。
- `v0.2.0` subagent shared workspace 回归仍通过。
- `v0.3.0` worktree 模式只在显式 `--worktree` 时启用。
- shared workspace 仍是默认 subagent 模式。
- 每个 topic 最多一条主 active path。
- subagent path 的生命周期状态仍是 `pending`、`paused` 或其他原本状态，不因 subagent 自动变为 `active`。
- `agent_run` 只表示执行状态，不替代 path 生命周期状态。
- `agent_run.status` 使用合法枚举值。
- `agent_run.mode = "subagent"`。
- `agent_run.context_mode` 使用 `clean` 或 `informed`。
- 非 worktree run 不包含 `agent_run.worktree`。
- worktree run 包含合法 `agent_run.worktree`。
- worktree path 和 branch 在冲突时不复用已有非空目录或已有 branch。
- `.worktrees/` 安全处理只在确认后发生。
- `list`、`show`、`map`、`map text` 都能展示紧凑 subagent 状态。
- worktree run 的 `list` 和 `map` 显示紧凑 worktree 状态。
- worktree run 的 `show` 展开 worktree path、branch、base、changed files 和 diff summary。
- subagent report 必须经过用户确认才写入 path update。
- 拒绝 subagent report update 时，`agent_run.status` 保持 `reported`。
- `--allow-shared-code` 不跳过 Trailmap 写入确认。
- `--worktree` 与 `--allow-shared-code` 互斥。
- 无效 `--base <ref>` 不 fallback 到 `HEAD`。
- 共享工作区风险在未显式接受时可见。
- retained worktree 改动不会在 `resume clean` 时自动应用到主工作区。
- Trailmap 不自动清理 worktree。
- 除用户确认的 `--worktree` branch/worktree 创建外，测试过程中没有发生 Trailmap 自动 Git 操作。
